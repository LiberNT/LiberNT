# プルリクエストの管理ルール

> [English](../../PULL_REQUEST_MANAGEMENT.md) | [中文](../zh-CN/PULL_REQUEST_MANAGEMENT.md) | [Français](../fr-FR/PULL_REQUEST_MANAGEMENT.md) | [Español](../es-ES/PULL_REQUEST_MANAGEMENT.md) | **日本語** | [العربية](../ar-MA/PULL_REQUEST_MANAGEMENT.md) | [Українська](../uk-UA/PULL_REQUEST_MANAGEMENT.md)

オープンなまま放置された PR の数を適切に保つため、次のルールを考慮してください。
- PR に 1 つ以上の承認があれば、追加のコメントを 1 週間待ったあとでマージできます。
  - 変更に 3 つ以上の承認がある場合、または十分に些細だと判断した場合は、すぐにマージしてかまいません。
- PR が長いあいだ「changes requested」のままで、作者が作業している様子がない場合は、クローズします。
  - 目安: 小さな PR なら 2 週間。大きな PR ならもっと長くてもかまいません。
  - 追加のコメントがある場合や新しい変更が加えられた場合は、いつでも PR を再オープンできます。
- 特定の人のレビューが必要な場合は、その人に PR をアサインしてください。GitHub の「review requested」機能だけに頼らないでください。
- PR のラベルがあることを忘れないでください。プルリクエストに適切なラベルを付けて、その範囲を示したり、注目を集めたり、単に探しやすくしたりできます。
- コメントするためだけに、目にしたものすべてにコメントする必要はありません。GitHub でも、Discord でも、Matrix でも同じです。

また、協力してくれるコントリビューターに失礼な印象を与えないよう、次のことは控えてください。
- 無関係な作業をコントリビューターに頼むこと
- 理由を示さずにクローズすること
- すぐに書き直すつもりでマージすること

PR をマージする前に、[貢献のルール](CONTRIBUTING.md#ルールと推奨事項)に従っていることを確認してください。特に重要なのは次の点です。
- 作者が PR のすべてのコミットに実在するメールアドレスを指定していることを確認する
- PR にコードや翻訳が含まれる場合は、作者が PR のすべてのコミットでニックネームや別名ではなく正式な氏名を指定していることを確認する
- PR にメディア（壁紙、テーマ、アイコン、サウンド）やコード外のドキュメントが含まれる場合は、作者が PR のすべてのコミットで名前または別名を指定していることを確認する
- PR がコードとメディアの変更を含む場合は、コードを含む PR として扱う
- PR に「Squash and merge」方式を使う前の重要な注意:
  - GitHub プロフィールの作者名がコミットの名前と一致していることを確認する。一致していない場合は、作者に設定を依頼する。
  - 作者が GitHub プロフィールに名前を設定したくない場合:
    - PR に「no squash merge」ラベルを付ける必要があります。
	- すべてのコミットメッセージが [.gitmessage](../../.gitmessage) のとおりに正しく書かれていることを確認する。
	- 最後に、この場合 PR は「Rebase and merge」方式か手作業でマージする必要があります。
  - PR の「Squash and merge」ボタンを押すと、作者が no-reply のメールアドレスを使っていないことを確認できます。
  コミットメッセージの下に次のテキストが表示されます: `This commit will be authored by <address@email.com>`
